# 每周一数据更新标准操作手册（6步照做版）

> 这份就是每周操作清单。按顺序执行，不要跳步。

## 你可能见过两套 git 命令——每周只用下面这一套

| 场景 | 该用哪条 |
|------|----------|
| **每周一例行更新数据**（99% 的情况） | 跑完脚本后：`git add` **只加** `data/warehouse/ui_payload.json` 和 `data/warehouse/weekly_metrics.json`，再 commit、push（见第 4～5 步）。 |
| **偶尔改动了脚本 / 手册 / `.gitignore`** | 在完成上面「两个 JSON」提交的前提下，或在同一次提交里 **额外** `git add` 你改过的那些文件（不要把 `data/` 里的大 Excel 一起加进来）。 |

另一长串（同时 `git add .gitignore`、`docs/`、`scripts/run_monday_update.py`）只是**仓库维护时**用过一次的示例，**不要当成每周固定命令**。

## 第 1 步：进入项目目录

```bash
cd "/Users/weiwei/餐厅周度经营看板_改"
```

## 第 2 步：一键重建（默认自动从上次结果往后算）

```bash
PYTHONPATH=. python3 scripts/run_monday_update.py
```

说明：
- 脚本默认自动取当前 `ui_payload` 最后一周的下一周作为边界；
- 默认只追加新周，不重算已存在历史周。

如果要修历史（手动指定起点）：

```bash
PYTHONPATH=. python3 scripts/run_monday_update.py --recompute-from 2026-03-16
```

## 第 3 步：快速核对（可选）

```bash
python3 - << 'PY'
import json
o=json.load(open('data/warehouse/ui_payload.json',encoding='utf-8'))
for s in ['夕佳悦','紫竹']:
    print('\n',s)
    for wk in ['2026-03-16','2026-03-23','2026-03-30','2026-04-06','2026-04-13']:
        r=o['stores'][s]['weeks'][wk]['productDetails']['returns']
        print(wk,'退/换菜',r['count'])
PY
```

## 第 4 步：提交（只提交看板产物）

```bash
git add data/warehouse/ui_payload.json data/warehouse/weekly_metrics.json
git commit -m "weekly update data"
```

> 说明：如果本周有代码改动（例如修逻辑），再额外 `git add` 对应代码文件。

## 第 5 步：推送

```bash
git push origin main
```

## 第 6 步：线上刷新检查

1. 打开：`https://w10978876-design.github.io/restaurant-weekly-dashboard/`
2. 强刷：`Cmd + Shift + R`
3. 检查本周数据是否更新

---

## push 失败时怎么做（唯一应急）

先换网络（推荐手机热点）后重试：

```bash
git -c http.version=HTTP/1.1 push origin main
```

---

## 注意（非常重要）

- 不要执行带 `#` 的注释行。
- 平时只用第 2 步自动模式；只有修历史才使用 `--recompute-from`。
